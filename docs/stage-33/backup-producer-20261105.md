# Streaming backup producer

`infra/operations/produce-backup.py` executes an explicit trusted command argument
list without a shell. It requires PostgreSQL custom-format magic (`PGDMP`), streams
stdout directly through authenticated CMS encryption, and requires both producer
and encryption processes to exit successfully. Partial output followed by failure,
empty/non-custom output, encryption failure and pipeline timeout cannot publish a
package. A dedicated producer process group also covers descendants holding the
pipe open. Diagnostics and environment values are never printed.

Before starting the command, the actual recipient certificate and signing public
key must match independently supplied SHA-256 pins. The certificate must be valid
and use RSA of at least 3072 bits. Certificate/public/private-key/passphrase inputs
are sealed snapshots. The private key is a separate signing key; no recipient
private decryption key is required or generated by the backup producer.

The resulting encrypted ciphertext is signed with the existing RSA-PSS manifest,
then independently verified against the supplied backup/application/boundary/time
context. Only then is a complete ZIP containing exactly `backup.cms` and
`manifest.json` atomically hard-linked to the new destination with 0600 permissions.
Existing files and symlinks are never overwritten. The containing directory is
fsynced. No plaintext dump file is created by this tool. A crash may leave encrypted
staging data, which needs normal housekeeping; filesystem durability still depends
on the actual storage. Publication fsync failures are reported as failures even if
a complete package has already become visible; operators must inspect it rather
than overwrite it. There is no automatic retry.

The command must be controlled by the operator and select the correct database
and matching pg_dump version. A producer exit code and PGDMP header are not a
proof of a complete or independently approved database snapshot. Created-at marks
the pipeline start, not an independently attested PostgreSQL transaction time.
Never pass credentials in command arguments; use the existing protected runtime
binding. This tool does not provision credentials or select a live database.

Nine local boundary tests plus a CI-only real PostgreSQL producer/restore test
cover completion, producer failure after partial output, empty/wrong-format output,
timeouts before/after output, encryptor failure and pipeline termination, wrong recipient before command execution, mismatched
signing key, existing-output preservation and invalid command/timeout. The real
CI test creates a separate synthetic source database, runs actual pg_dump through
the new pipeline, verifies/decrypts the package and runs pg_restore into another
database, checking exact decimal content. The existing current-schema two-boundary
privacy/stock/B2B restore matrix remains a separate required gate.

Invocation uses named flags `--output`, `--certificate`, `--signing-public`,
`--signing-private`, `--expected-recipient`, `--expected-signer`, `--backup-id`,
`--application-sha`, `--boundary`, optional `--timeout` (pipeline seconds, at most
3600) and `--passphrase` (a protected file path). Put `--` before the trusted
producer command and arguments. CLI stdout contains status only.

## Remaining production gates

No live database backup, service change, schedule, remote upload, key provisioning,
retention/RPO/RTO approval or monitoring is performed. This is a producer building
block, not an operating backup service. Off-host storage/access, separate recipient
and signer custody/rotation/revocation, trusted recovery approvals, monitored
scheduling and failure alerts, capacity limits, protected plaintext restore/crash
cleanup and actual independent-key production recovery remain open. Signing time
is not bounded by the pipeline timeout. The final ZIP is encrypted data, not an
archive to extract blindly; consumers must enforce fixed entries and size limits.
